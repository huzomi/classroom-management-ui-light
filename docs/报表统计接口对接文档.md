# 报表统计 — 接口对接文档

> 本文档用于指导另一个系统对接同一套报表统计后端接口，涵盖两个核心页面：**数据统计分析页**和**数据看板（大屏）页**，包含所有接口定义、数据结构、业务逻辑及注意事项。

---

## 一、页面功能概览

报表统计模块包含两个独立页面：

### 页面 A：数据统计分析（edu/home）

| 功能 | 说明 |
|------|------|
| **筛选栏** | 年份、季节、月份三级筛选（季节和月份互斥），支持导出报表按钮 |
| **统计卡片** | 4 张卡片：刷卡最多教室、刷卡最多学院、刷卡最多个人、最长使用教室 |
| **刷卡教室排名** | 横向柱状图 Top 10，支持升序/降序切换 |
| **学院刷卡活跃度排名** | 折线面积图 Top 10，支持升序/降序切换 |
| **刷卡达人榜** | 列表形式 Top 5，展示姓名、学院、刷卡次数，支持升序/降序切换 |
| **使用教室排名** | 纵向柱状图 Top 10，按使用时长排名，支持升序/降序切换 |

### 页面 B：数据看板/大屏（edu/statistics/data-dashboard）

| 功能 | 说明 |
|------|------|
| **顶部总览** | 4 张卡片：教室总数、普通教室、智慧教室、会议教室 |
| **教室使用情况** | 左侧表格，按校区/教学楼展示教室数、已用、空闲 |
| **教室使用时间** | 左侧排名列表，可切换"使用时间最高/最低" |
| **最新工单记录** | 左侧列表，展示最新的报修/工单记录 |
| **教室状态** | 右侧 3D 饼图：上课教室、空闲教室、故障教室、下课教室 |
| **设备总数** | 右侧分页卡片网格，展示各类设备数量 |
| **设备状态** | 右侧柱状图，按使用/空闲展示各设备状态 |
| **教学楼使用频次走势图** | 底部面积折线图，按日期展示教学楼使用频次 |
| **地图** | 高德地图 3D 模式，展示楼栋标记点，点击弹窗显示教室使用率 |
| **校区选择器** | 可拖拽的校区切换面板，切换后地图中心移动 |

## 三、接口详细说明（页面 A：数据统计分析）

### 3.1 刷卡教室排行

- **URL**: `POST /report/room/page`
- **Content-Type**: `application/json`
- **请求参数**:

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| sort | number | 是 | 排序方式：1-从小到大，2-从大到小 |
| year | number | 否 | 年份，如 2026（不传则不限年份） |
| month | number | 否 | 月份 1-12（与 season 互斥，不传则不限月份） |
| season | string | 否 | 季节中文名（与 month 互斥，不传则不限季节） |
| page | number | 是 | 页码，从 1 开始 |
| pageSize | number | 是 | 每页条数（前端默认 10） |

- **响应数据结构**:

```json
{
  "records": [
    {
      "roomCode": "一号教学楼 101",
      "payCount": 320
    }
  ],
  "total": 50,
  "size": 10,
  "current": 1,
  "pages": 5
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| roomCode | string | 教室编号/名称 |
| payCount | number | 刷卡次数 |

---

### 3.2 学院刷卡活跃度排名

- **URL**: `POST /report/college/page`
- **Content-Type**: `application/json`
- **请求参数**: 与刷卡教室排行完全一致（sort、year、month、season、page、pageSize）
- **响应数据结构**:

```json
{
  "records": [
    {
      "college": "计算机学院",
      "payCount": 1200
    }
  ],
  "total": 20,
  "size": 10,
  "current": 1,
  "pages": 2
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| college | string | 学院名称 |
| payCount | number | 刷卡次数 |

---

### 3.3 刷卡达人榜

- **URL**: `POST /report/personal/page`
- **Content-Type**: `application/json`
- **请求参数**: 与刷卡教室排行完全一致（sort、year、month、season、page、pageSize）
- **前端默认**: `pageSize = 5`（只取 Top 5）
- **响应数据结构**:

```json
{
  "records": [
    {
      "name": "张三",
      "cardNo": "2024001",
      "college": "计算机学院",
      "payCount": 85
    }
  ],
  "total": 100,
  "size": 5,
  "current": 1,
  "pages": 20
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| name | string | 姓名 |
| cardNo | string | 卡号 |
| college | string | 所属学院 |
| payCount | number | 刷卡次数 |

---

### 3.4 使用教室排名

- **URL**: `POST /operationLog/room/useTime`
- **Content-Type**: `application/json`
- **请求参数**:

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| sort | number | 是 | 排序方式：1-从小到大，2-从大到小 |
| year | number | 否 | 年份 |
| month | number | 否 | 月份 1-12（与 season 互斥） |
| season | string | 否 | 季节中文名（与 month 互斥） |

- **⚠️ 注意**: 此接口**不是分页接口**，不传 `page` 和 `pageSize`，直接返回数组。
- **响应数据结构**:

```json
[
  {
    "roomName": "一号教学楼 101",
    "time": 128
  },
  {
    "roomName": "一号教学楼 102",
    "time": 115
  }
]
```

| 字段 | 类型 | 说明 |
|------|------|------|
| roomName | string | 教室名称 |
| time | number | 使用时长（单位：小时） |

## 四、接口详细说明（页面 B：数据看板/大屏）

### 4.1 教室大屏数据

- **URL**: `GET /common/room/bigScreen`
- **请求参数**: 无
- **⚠️ 注意**: 框架的 `defHttp` 默认会拼接 `urlPrefix`（一般为 `/jeecg-boot`），实际完整 URL 为 `/jeecg-boot/common/room/bigScreen`
- **响应数据结构**:

```json
{
  "classRoomCount": {
    "regularClassroomCount": 0,
    "smartClassroomCount": 40
  },
  "classUse": [
    {
      "campus": "阳光校区",
      "building": "一号教学楼",
      "campusId": "xxx",
      "buildingId": "xxx",
      "classroomCount": 40,
      "usedCount": 1,
      "idleCount": 39
    }
  ],
  "classUseTime": {
    "useTimeMax": 128,
    "useTimeMin": 8
  },
  "latestWorkOrderRecord": [
    {
      "workOrderId": "xxx",
      "description": "111 教室前部照明灯损坏",
      "createTime": "2023/02/15 17:10:27"
    }
  ],
  "classRoomStatus": {
    "progressCount": 1,
    "idleCount": 1,
    "faultCount": 40,
    "offlineCount": 0
  },
  "equipmentCount": {
    "电脑": 31,
    "投影机": 18,
    "幕布": 18,
    "静音": 2,
    "音量": 2,
    "录制主机": 2
  },
  "equipmentStatus": null
}
```

#### 4.1.1 classRoomCount — 教室数量统计

| 字段 | 类型 | 说明 |
|------|------|------|
| regularClassroomCount | number | 普通教室数量 |
| smartClassroomCount | number | 智慧教室数量 |

前端将两者相加得到「教室总数」：`totalRooms = regularClassroomCount + smartClassroomCount`

#### 4.1.2 classUse — 教室使用情况（数组）

| 字段 | 类型 | 说明 |
|------|------|------|
| campus | string | 校区名称 |
| building | string | 教学楼名称 |
| campusId | string | 校区 ID |
| buildingId | string | 教学楼 ID |
| classroomCount | number | 教室数 |
| usedCount | number | 已使用（上课中） |
| idleCount | number | 空闲数 |

前端按 `campus` 字段分组，同一校区的数据归为一组，在表格中以校区行 + 数据行的形式展示。

#### 4.1.3 classUseTime — 教室使用时间

| 字段 | 类型 | 说明 |
|------|------|------|
| useTimeMax | number | 使用时长最大值 |
| useTimeMin | number | 使用时长最小值 |

⚠️ 当前接口仅返回最大/最小值，不返回具体教室名称和完整排名列表。

#### 4.1.4 latestWorkOrderRecord — 最新工单记录（数组）

| 字段 | 类型 | 说明 |
|------|------|------|
| workOrderId | string | 工单 ID |
| description | string | 工单描述 |
| createTime | string | 创建时间 |

#### 4.1.5 classRoomStatus — 教室状态

| 字段 | 类型 | 说明 |
|------|------|------|
| progressCount | number | 上课教室数 |
| idleCount | number | 空闲教室数 |
| faultCount | number | 故障教室数 |
| offlineCount | number | 下课教室数 |

#### 4.1.6 equipmentCount — 设备总数

类型为 `Record<string, number>`，即 `{ 设备名称: 数量 }` 的键值对。

```json
{
  "电脑": 31,
  "投影机": 18,
  "幕布": 18
}
```

前端将其转为数组展示，每页 6 个，支持翻页。

#### 4.1.7 equipmentStatus — 设备状态

类型不固定（`unknown`），前端做了多种格式兼容，可能为以下任一形态：

**形态 1**（推荐）:
```json
{
  "使用": { "电脑": 35, "投影机": 12 },
  "空闲": { "电脑": 0, "投影机": 6 }
}
```

**形态 2**:
```json
{
  "use": { "电脑": 35, "投影机": 12 },
  "idle": { "电脑": 0, "投影机": 6 }
}
```

**形态 3**:
```json
{
  "电脑": { "use": 35, "idle": 0 },
  "投影机": { "use": 12, "idle": 6 }
}
```

**为 null 时**: 前端默认将 `equipmentCount` 中的所有数量视为「使用」，「空闲」为 0。

## 六、业务逻辑与注意事项

### 6.1 筛选条件互斥（页面 A）

- **季节**和**月份**互斥：选择季节时自动清空月份，选择月份时自动清空季节
- 年份、季节、月份均为可选参数，不传表示不限
- 筛选条件变化时，4 个接口同时重新请求

### 6.2 排序切换联动（页面 A）

- 每个图表区域都有独立的升序/降序开关
- 切换排序时仅重新请求对应的单个接口
- 但筛选条件（年份/季节/月份）变化时，4 个接口全部重新请求

### 6.3 统计卡片数据来源（页面 A）

统计卡片的数据**不是独立接口**，而是从排名接口的返回结果中提取：

| 卡片 | 数据来源 | 取值逻辑 |
|------|---------|---------|
| 刷卡最多教室 | `/report/room/page` | 降序时取第 1 条的 `roomCode` 和 `payCount` |
| 刷卡最多学院 | `/report/college/page` | 降序时取第 1 条的 `college` 和 `payCount` |
| 刷卡最多个人 | `/report/personal/page` | 降序时取第 1 条的 `name` 和 `payCount` |
| 最长使用教室 | `/operationLog/room/useTime` | 降序时取第 1 条的 `roomName` 和 `time` |

### 6.4 大屏数据一次性获取（页面 B）

- 大屏页面只调用一个接口 `GET /common/room/bigScreen`，一次返回所有数据
- 没有筛选条件，不支持按时间/校区等维度筛选（前端校区选择器仅控制地图位置，不重新请求数据）
- 页面进入时自动全屏，退出时还原

### 6.5 大屏地图相关

- 使用**高德地图** JS API 2.0，需要 Key 和安全密钥
- 默认 Key: `f5d62248589564702151648ba28ab4a9`（可通过环境变量 `VITE_AMAP_KEY` 覆盖）
- 默认安全密钥: `1072dedcda48926d55ed87c1bb31d700`（可通过 `VITE_AMAP_SECURITY_CODE` 覆盖）
- 地图配置：3D 模式，暗色主题 `darkblue`，俯仰角 38°
- 楼栋标记图标路径：`/resource/img/building-3d.png`（需放在 public 目录下）
- 点击楼栋标记弹窗显示：教室数量、使用数、当前使用率（使用数/教室数×100%）

### 6.6 大屏教室使用时间（页面 B）

- 当前接口仅返回 `useTimeMax` 和 `useTimeMin` 两个数值
- 前端以「最高使用时长」和「最低使用时长」两条记录展示
- 支持切换 Tab：「使用时间最高」/「使用时间最低」

### 6.7 设备总数分页展示（页面 B）

- 设备总数以 2×3 网格卡片展示，每页 6 个
- 超过 6 个设备类型时出现翻页按钮（鼠标悬浮时显示）

### 6.8 设备状态图表交互（页面 B）

- 柱状图展示使用/空闲两个系列
- 右上角有自定义图例，可点击切换系列显示/隐藏
- 使用颜色：蓝色 `#1890ff`；空闲颜色：绿色 `#52c41a`

### 6.9 教学楼使用频次走势图（页面 B）

- 底部面积折线图，暗色主题
- 多系列（每栋教学楼一条线），支持图例切换
- X 轴为日期，Y 轴为使用时长（单位：时）
- ⚠️ 当前前端走势图数据为**硬编码**，未接入后端接口。如需动态数据需后端提供额外接口。

### 6.10 教室使用情况表格分组逻辑（页面 B）

- 后端返回的 `classUse` 数组按 `campus` 字段分组
- 前端构建表格行时，每个校区先插入一行"校区标题行"（合并所有列），再展示该校区下的教学楼数据行

### 6.11 导出报表（页面 A）

- 当前前端导出按钮仅弹出 `message.success('报表导出中，请稍候...')`，未实际调用后端导出接口

## 七、图表配置参考

### 7.1 刷卡教室排名 — 横向柱状图

- 图表类型：`bar`（水平方向）
- Y 轴：教室名称（category）
- X 轴：刷卡次数（value）
- 柱子宽度：16px，右侧圆角
- 渐变色：`#1890ff` → `#69c0ff`
- 标签显示在柱子右侧

### 7.2 学院刷卡活跃度排名 — 折线面积图

- 图表类型：`line`（smooth 平滑曲线）
- X 轴：学院名称（超过 4 字省略显示）
- Y 轴：刷卡人次
- 线条颜色：`#52c41a`，宽度 3px
- 面积渐变：`rgba(82, 196, 26, 0.4)` → `rgba(82, 196, 26, 0.05)`
- 圆点大小：8px，白色边框

### 7.3 使用教室排名 — 纵向柱状图

- 图表类型：`bar`（垂直方向）
- X 轴：教室名称（category）
- Y 轴：使用时长（小时）
- 柱子宽度：30px，顶部圆角
- 渐变色：`#1890ff` → `#69c0ff`

### 7.4 教室状态 — 3D 饼图（大屏）

- 使用 `echarts-gl` 的 `surface` 类型实现 3D 效果
- 自动旋转，3 秒轮播高亮
- 中心显示当前高亮分片的数值和名称
- 内径比 0.8（环形）

### 7.5 设备状态 — 柱状图（大屏）

- 暗色主题
- 双系列：使用（蓝色 `#1890ff`）、空闲（绿色 `#52c41a`）
- 十字准心 tooltip

### 7.6 教学楼使用频次走势图（大屏）

- 暗色主题
- 面积折线图，smooth 平滑
- 多系列对应不同教学楼
- 每条线标记最大值点（`markPoint`）
- 图例右上角，白色文字
- 颜色组：`#3AFFBC`、`#FF9600`、`#29BAFB`、`#5090FF`

## 八、页面 A 完整数据流

```
页面加载
  ├── fetchRoomRankData()       → POST /report/room/page      → 更新教室排名图表 + 卡片1
  ├── fetchCollegeActivityData() → POST /report/college/page    → 更新学院排名图表 + 卡片2
  ├── fetchTopUserData()         → POST /report/personal/page   → 更新达人榜列表 + 卡片3
  └── fetchUsageRankData()       → POST /operationLog/room/useTime → 更新使用时长图表 + 卡片4

筛选条件变化（年份/季节/月份）
  └── 重新调用以上 4 个函数

排序开关变化
  └── 仅重新调用对应的 1 个函数
```

## 九、页面 B 完整数据流

```
页面加载
  ├── enterFullscreen()     → 进入全屏
  ├── initDeviceStatusChart() → 初始化设备状态柱状图
  ├── initBuildingTrendChart() → 初始化走势图（硬编码数据）
  └── fetchBigScreen()      → GET /common/room/bigScreen
       ├── overview          → 教室总数/普通/智慧/会议
       ├── roomUsageTable    → 教室使用情况表格
       ├── roomTimeHighest/Lowest → 使用时间最高/最低
       ├── workOrderList     → 最新工单记录
       ├── roomStatusLegend  → 教室状态 3D 饼图
       ├── deviceTotalList   → 设备总数卡片
       └── deviceStatusData  → 设备状态柱状图
```
